# Standard fossil table

Use a comma-separated UTF-8 CSV with the header in `templates/fossils.csv`.
Keep all columns; leave unavailable optional values empty. Do not insert units
or plus/minus symbols into numeric columns. `16780 +/- 40` becomes `16780` in
`age_14c_bp` and `40` in `error_14c_bp`. Missing is empty, **not zero**.

| Column | Required / meaning |
|---|---|
| `record_id` | Required unique row identifier. Preserve source IDs where possible. |
| `specimen_id` | Required physical specimen identifier. Only one accepted dating estimate per specimen; redates do not create new fossils. |
| `site_id` | Required locality identifier, shared by fossils from the same locality. Governs folds/bootstrap. Use one agreed coordinate per site. |
| `taxon` | Required accepted taxon label; document synonym/taxonomic decisions yourself. |
| `site` | Human-readable locality name; recommended. |
| `longitude` | Required decimal degrees east, WGS84; negative in the west. |
| `latitude` | Required decimal degrees north, WGS84; Southern Hemisphere not supported by this archive adapter. |
| `coordinate_uncertainty_km` | Optional nonnegative radius/approximate uncertainty, with interpretation in notes. Preserved, not automatically propagated. City-centre coordinates are not precise fossil coordinates. |
| `date_type` | Required `radiocarbon` or `calibrated_range`. |
| `age_14c_bp` | Raw conventional radiocarbon BP for `radiocarbon`; not calendar BP. |
| `error_14c_bp` | Raw radiocarbon 1-sigma laboratory error for `radiocarbon`. |
| `cal_young_bp` | Younger endpoint in calendar years BP for `calibrated_range`. |
| `cal_old_bp` | Older endpoint in calendar years BP for `calibrated_range`; >= young endpoint. |
| `calibration_reference` | Required for supplied calendar intervals; record source, curve and interval definition. |
| `lab_code` | Recommended laboratory identifier, useful for deduplication/source audit. |
| `material` | Recommended dated material and relevant notes. |
| `quality_class` | Required your explicit quality label; software does not certify it. Define labels in your study notes. |
| `include` | Required literal TRUE or FALSE. No automatic MEGA14C reliability filter is applied. |
| `exclusion_reason` | Required if include is FALSE. Keep rejected rows for the audit. |
| `reference` | Required source DOI/citation/table/database version. |
| `notes` | Optional pretreatment, contextual association, uncertainty and taxonomy notes. |

Do not recalibrate a calendar age as though it were a radiocarbon age. Prefer
raw laboratory ages/errors when available. A date associated with a layer is not
automatically a direct fossil date: make that distinction in quality/material
notes and decide whether it belongs in the main or sensitivity analysis.

Non-finite minimum ages (e.g. `>45000`), unspecified errors, BC/BCE ranges and
stratigraphic estimates need explicit processing/review before this table. The
software does not guess errors, combine dates from different individuals, or
decide whether a sample was adequately purified.

Multiple papers/database rows can refer to the same bone. Reconcile specimen and
lab identifiers before setting `include=TRUE`. Distinct specimens from one site
may remain, but share a `site_id`; many dates from one site do not provide many
independent spatial localities. Clustering can still affect the model even with
site-grouped validation and site bootstrapping.

The synthetic table generated by `examples/make_demo.R` shows a fully populated
format, one excluded record and one already calibrated interval. It contains no
real specimens. Real fossils must come from your reviewed, cited source table.
